Ошибки по доменам в AVIN

Пока в AVIN достаточно одного AvinError, но в перспективе глобальный enum может стать слишком широким: trading-система состоит из множества независимых подсистем, и сваливать все их ошибки в один тип может оказаться неудобно.

Вероятный здоровый путь — не вводить отдельный BasicError, а дать каждому крупному crate свой error domain и при необходимости повторять в нем простые общие категории.

pub enum ModelError {
    Value(String),
    Parse(String),
    Missing(String),

    InstrumentInfo {
        message: String,
        source: Option<Box<ModelError>>,
    },
}

pub enum StorageError {
    NotFound(...),
    Format(...),
    Io(...),
}

pub enum ServiceError {
    Network(...),
    Auth(...),
    RateLimit(...),
}

То есть нынешний AvinError со временем может не усложняться бесконечно, а естественно разделиться по границам подсистем.

Принцип передачи ошибок

Primitive/general error не нужно автоматически оборачивать в более высокоуровневую ошибку.

Если текущий слой добавляет новый смысл — создаем более высокоуровневую ошибку и сохраняем нижнюю как source.

Если нового смысла нет — просто конвертируем/пропускаем ошибку через error type текущего API.

Если функция сама находится на низком уровне — возвращаем ее собственную ошибку напрямую.

Иными словами, error chain должен отражать реальные уровни смысла, а не архитектурную бюрократию.

Пока архитектуру фиксировать рано. Оставляем один AvinError, наблюдаем реальные случаи и делим ошибки по доменам только тогда, когда глобальный enum начнет мешать.
